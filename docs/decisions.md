## Choices made while building

| Milestone | Choice | Why |
|---|---|---|
| M0 | Dependencies added: `golang.org/x/tools` v0.50.0 (named in PLAN), `github.com/uudashr/gocognit` v1.2.1 (named), `github.com/BurntSushi/toml` v1.6.0 (approved by owner). `go.yaml.in/yaml/v3` is approved for `terms.yaml` and will be added when the glossary is first read (M1 `explain`). | CLAUDE.md rule 9 |
| M0 | CLI uses the standard `flag` package, with flags allowed after positional arguments (`qtldr show applyTiered --json`). Global flags work before or after the command. | Standard library first |
| M0 | New global flag `-C <dir>` ("run as if started in dir"), like `go -C` / `git -C`. The module root is the nearest `go.mod` at or above that dir. | The fixture has its own `go.mod`; `analyze ./testdata/ledger/...` cannot cross module boundaries. |
| M0 | The snapshot has a `kind: "module"` node (ID = module path, name = last path element without `/vN`, e.g. `ledger`). Packages' `parent` points at it. | §5.2 references the module as `parent` but never defines it. |
| M0 | Package node `name`/`dir` = path relative to the module (`internal/pricing`); the root package gets `dir: "."` and the module's short name. | Matches §5.2 example. |
| M0 | Method nodes: ID `<pkg>.<Type>.<Method>`, `name: "Type.Method"`, plus `recv` and `ptr_recv` fields. | §5.1 says the pointer receiver is a field; crap4go also names methods `Type.Method`. |
| M0 | `calls_dynamic` edges point at the interface method ID (`…/httpapi.RuleSource.LoadRules`), which is not itself a node; the edge is kept when the interface type node exists. | §6.2 wording. The UI can draw it to the interface type. Revisit in M5 with VTA. |
| M0 | Edges whose endpoints are not nodes (calls into excluded or generated files) are dropped. | Avoid dangling edges. |
| M0 | Duplicate function IDs (several `init` funcs) get `#<file>` then `#<file>:<line>`. | §15; `init` is the case a single go/packages load can produce. |
| M0 | External module display name: path without the host element and `/vN` (`github.com/go-chi/chi/v5` → `go-chi/chi`). With `show_stdlib = true`, stdlib packages appear as external nodes keyed by import path. | Matches the mockup's `go-chi/chi`, `jackc/pgx`. |
| M0 | Body hash = SHA-256 of `go/printer` output of the FuncDecl without doc comment, **with blank lines removed**. go/printer drops comments for non-File nodes but keeps line breaks, so removing a comment line would otherwise leave a blank line and change the hash. | §6.2 intent: formatting and doc edits don't invalidate results. Tested in `TestBodyHash`. |
| M0 | `loc` = `end_line − line + 1` (the `func` line to the closing brace; doc comment excluded). | §5.2 example: applyTiered lines 20–48 → loc 29. |
| M0 | The golden file stores the whole scanned graph (nodes incl. signatures and body hashes, edges, cc/cognitive/loc). **Purity is not in the M0 golden**: purity is an M1 feature; the golden will be regenerated when it lands. `implements` edges are M5 and absent. | §12 lists purity in the golden, §13 schedules purity for M1. |
| M0 | `worst` accepts `cognitive` and `cc` in M0; `crap`, `coverage`, `mutation` exit 2 with "not measured yet". `show` prints CRAP/Coverage/Mutation as "not measured". | No silent zeros (CLAUDE.md rule 7). |
| M0 | `init` never overwrites an existing `.qtldr.toml`; it appends only missing `.gitignore` rules under a `# qtldr` comment. qtldr's own `.gitignore` uses `**/.qtldr/...` so the fixture's state is ignored too. | Idempotent. |
| M0 | The fixture was written so the M1 targets fall out of real runs: crap4go already reports `BestRule` CRAP 30.0 (CC 5, 0%) and `applyTiered` CRAP 14.1 (CC 11, 70.6% = 12/17 statements). Its deps: chi v5.3.2, pgx v5.11.0. | PLAN §12/§13 M1 acceptance |
| M0 | staticcheck: the installed binary was built with an older Go and cannot read Go 1.27 export data; run `go run honnef.co/go/tools/cmd/staticcheck@latest ./...` (v0.8.1 is clean). | — |

| M1 | **Purity rule 2, sentinel errors (option B, owner's call):** a package-level `var` of type `error` counts like a constant when (module vars) it is initialized with `errors.New`/`fmt.Errorf` and nothing in the module assigns it or takes its address; (vars of other modules / stdlib, e.g. `io.EOF`, `sql.ErrNoRows`) nothing in the module assigns it. Any other package-level var read or written is an effect ("reads var store.defaultDSN"). Result on the fixture matches the mockup: money, order, pricing pure; ledgerd, httpapi, store effectful. | Sentinel errors cannot be `const` in Go; without this almost every package is "effectful". |
| M1 | Purity rule 1 checks parameters and results (not the receiver); a type "contains" an effectful type through pointers, slices, arrays, maps and func signatures, not through struct fields of named types. Rule 4 table: any function or method of os, os/exec, os/signal, os/user, io, io/ioutil, io/fs, net and net/* (incl. net/url, per "net/*"), math/rand(/v2), crypto/rand, log, log/slog, log/syslog, syscall; plus time.Now/Sleep/Since/Until/After/AfterFunc/Tick/NewTimer/NewTicker and fmt.Print*/Fprint*/Scan*/Fscan*. Calls into non-stdlib external modules are not effects by themselves (PLAN's table does not list them). | PLAN §6.2 lists; extras are the same kind (clock, I/O). |
| M1 | `implements` edges are produced now (PLAN puts them in M5) because rule 5 needs them: a `calls_dynamic` edge is pure only if the interface has at least one module implementation and all are pure. No implementation in the module → effectful. Generic types and empty interfaces are skipped. | Rule 5 cannot be applied without them. |
| M1 | Package combined grade = worst combined grade among its functions ("a parent shows its worst child"). PLAN §5.2's example (pricing combined 1 with CRAP 2, mutation 1) does not follow either reading exactly; the rule text wins. A package with no functions has no grades and is pure. Package "worst" = highest CRAP, ties → lowest combined grade. | PLAN §7.4 |
| M1 | CRAP uses the exact covered/statements ratio, not the rounded percent. | 12/17 must give 14.08 (crap4go: 14.1). |
| M1 | Coverage runs as **one** `go test` invocation over the scope's packages (fast; go builds test binaries in parallel). Failed packages are read from `FAIL\t<pkg>` summary lines; their blocks are dropped and their coverage is "not measured" with the log path (`.qtldr/logs/coverage-<time>.log`). A run package's function whose file has no profile blocks has zero statements (not "not measured"). | PLAN §7.1 |
| M1 | Coverage cache `.qtldr/cache/coverage.json` (gitignored) keeps each function's result with its body hash and **line offsets from the function start**, so a function that only moved keeps correct line numbers; a changed body is shown "stale". | Structure-only `analyze` still shows coverage. |
| M1 | Line states follow PLAN's overlap rule literally, so the closing `}` of an uncovered block counts as uncovered ("tier.go:25–26"). Go's cover blocks end at the brace. | Kept to the spec; the source view can dim brace-only lines. |
| M1 | Churn: one `git log --since --format=%x00commit --name-only --relative --no-renames -- .` from the module root (so modules in a subdirectory of the repo work). File churn = commits touching the file; package churn = commits touching any file directly in its directory. | PLAN §6.2 churn |
| M1 | `check` scope from files (`check a.go`, hook payload) = every function in those files. `--fast` checks cognitive, and CRAP only where cached coverage is current; its "Not measured" lists only those kinds. Non-fast runs the tests of the scope's packages first. Markdown ≤ 60 lines: the functions table is cut first, then "not measured", notes, breaches, each ending "… and N more". | PLAN §8 |
| M1 | Hook mode finds the module from the edited file's directory (Claude Code may run from a repo root above the module), ignores non-Go and `_test.go` files, and logs runtime errors to `.qtldr/logs/hook-<time>.log` with exit 0. | Robust in monorepos. |
| M1 | `hook install` with neither flag installs both. The Claude merge keeps the user's key order (ordered JSON object) and never duplicates an identical entry. The git hook path comes from `git rev-parse --git-path hooks/pre-push`; it `cd`s to the module (`--show-prefix`) before `qtldr check --changed`. | PLAN §10 |
| M1 | New package `internal/analysis`: the one pipeline (scan → coverage → churn → metrics → snapshot) used by `analyze`, `check`, and later the server and MCP. Not in PLAN §2's layout. | One code path, same numbers everywhere. |
| M1 | qtldr's own `.qtldr.toml`: `coverpkg = "module"` (orchestration is tested through CLI tests), `cmd/qtldr/main.go` excluded (wiring only), and `coverage_min = 0`, `mutation_min = 0`, because CLAUDE.md/PLAN define qtldr's own gate as CRAP ≤ 8 + cognitive ≤ 15 (CRAP already weights coverage by complexity). `make ci` runs `qtldr check --all` on itself: 0 breaches at M1. | CLAUDE.md rule 5, PLAN §12 dogfood |
